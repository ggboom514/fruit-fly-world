果蝇世界 · 发版步骤
============================================================

给「发新版那一天」用的清单，照着从上往下走就行。

下面所有命令都在**项目根目录**跑（就是这个文件所在的目录）：

    C:\Users\Administrator\AppData\Roaming\CherryStudio\Data\Agents\
        2026-09-13\4afc789f-b05f-485a-875e-15786d4dfe2f\fruit-fly-pet

（`dist` 是指向 D:\ai game\fruit-fly-pet\dist 的快捷方式，两边是同一个地方。）


------------------------------------------------------------
先搞懂一件事：游戏怎么知道有新版本
------------------------------------------------------------

游戏**自己不知道**，它不会猜。它在网上读一张小纸条，纸条就是仓库里那个
version.json：

    {
      "version": "1.28.0",            ← 现在最新是几版
      "url": "https://pan.quark.cn/s/xxx",   ← 去哪儿下
      "note": "改了什么（可选）"
    }

读到 1.28.0，比自己手里的版本大，就提示「有新版本」。

⚠ **纸条不会自己更新。** 你发了 1.29.0、纸条上还写着 1.28.0，那么所有玩家
   的游戏都会说「已经是最新的」—— 能连上、能读到、一切正常，就是内容旧了。
   这是个**不报错的错**，所以最容易忘。下面第 4 步专门治它。


============================================================
发版当天：照着走
============================================================

------------------------------------------------------------
第 1 步 · 改版本号
------------------------------------------------------------

改两个文件：

  package.json          第 3 行   "version": "1.28.0"  →  "1.29.0"

 说明.txt              第 1 行   果蝇世界 v1.28.0
                       第 15 行  FruitFlyWorld-Setup-1.28.0.exe
                       第 19 行  FruitFlyWorld-1.28.0.exe
                       第 92 行  设置卡上的「版本 1.28.0」

⚠ 「说明.txt」是**要传给玩家的**，里面的文件名写错版本号，玩家照着找会找不到。
   这个文件同样不会自己更新。

⚠ 只有这两个文件是**必须**改的。README.md 和代码注释里也有几个 1.28.0，
   但那些都是「举例说明」，不影响功能，想顺手改就改，忘了也不会出事。


------------------------------------------------------------
第 2 步 · 自检
------------------------------------------------------------

三条都要绿：

    bun run check       语法检查（几秒）
    bun run sim         无头模拟器，几百条数值断言
    bun run selftest    真的开一个窗口把界面跑一遍

⚠ selftest 读写的是临时目录，碰不到你的真存档。
⚠ 如果 selftest 报 `Script failed to execute`，八成是 main.js 里那块自检
   模板字符串混进了反引号或 ${ —— 直接跑 `bun run check`，它会告诉你第几行。


------------------------------------------------------------
第 3 步 · 打包
------------------------------------------------------------

    bun run dist

产物在 dist\ 里。

⚠ **如果报 EBUSY（文件被占用）**：那是 Windows Defender 正占着刚解压出来的
   exe/dll，连改名都拒绝，重启才会松手。绕过去的办法是换个输出目录：

    node_modules\.bin\electron-builder.exe --win --x64 "-c.directories.output=$env:TEMP\ffw-build-129"

   然后手动把下面三个文件拷回 dist\：
     FruitFlyWorld-Setup-1.29.0.exe
     FruitFlyWorld-Setup-1.29.0.exe.blockmap
     FruitFlyWorld-1.29.0.exe
   最后删掉那个临时目录。

⚠ 打完包**验一下打包版**：

    %TEMP%\ffw-build-129\win-unpacked\FruitFlyWorld.exe --selftest

   要看到 [selftest] 通过 才算数。

⚠ **别拿 dist\FruitFlyWorld-1.29.0.exe --selftest 去验** —— 那是个免安装壳，
   它把自己解压出来再另起一个进程，**不继承输出**，你会看到「exit 0 但一个字
   都没有」，那个 0 只能证明壳没崩。


------------------------------------------------------------
第 4 步 · 换纸条（最容易忘的一步）
------------------------------------------------------------

    bun run manifest -- "https://pan.quark.cn/s/你的分享页" "1.29.0 改了什么"

这条命令会去读 package.json，看到是 1.29.0，就把 version.json 改成 1.29.0。

⚠ **不要手写 version.json。** 手写迟早会出现「package.json 改了、纸条忘了改」，
   而症状只是「检查更新一直说已是最新」，很难查。让命令读就不可能对不上。

⚠ note 那一栏是给玩家看的一句话，可以不写。


------------------------------------------------------------
第 5 步 · 把纸条推上去
------------------------------------------------------------

    git add version.json
    git commit -m "版本清单 1.29.0"
    git push

⚠ version.json 必须待在**仓库根目录**并提交进 git。raw 链接只认提交进仓库的
   文件 —— 放到 dist\ 里是没用的（那个目录整个在 .gitignore 里）。


------------------------------------------------------------
第 6 步 · 催一下 CDN 缓存
------------------------------------------------------------

浏览器打开一次这个网址就行，不用管它显示什么：

    https://purge.jsdelivr.net/gh/ggboom514/fruit-fly-world@main/version.json

为什么：游戏读纸条时中间隔着一个叫 jsDelivr 的中转站（国内才打得开 GitHub）。
它拿到纸条后会**自己存一份，存 12 小时**。你换了新纸条，它还在发旧的。

催它一下 = 告诉它「你手上那份作废了，去 GitHub 重拿」。

⚠ 不催也不会坏，只是**最坏要等半天**玩家才收到更新提示。


------------------------------------------------------------
第 7 步 · 传两个地方
------------------------------------------------------------

下载有**两条路**，主推夸克（国内快），GitHub Releases 当备用。

=== 7a 夸克网盘（主）===

把这四个拖进夸克的分享文件夹：

    dist\FruitFlyWorld-Setup-1.29.0.exe            安装版（推荐）
    dist\FruitFlyWorld-Setup-1.29.0.exe.blockmap   增量差分包
    说明.txt                                        给下载的人看的
    dist\FruitFlyWorld-1.29.0.exe                  免安装版

⚠ **不要传 version.json** —— 它是给程序抓的，而网盘不给程序抓。
   它只待在仓库里。

⚠ blockmap 现在没用上，但**别省**：少传了以后想加增量更新就只能重传全部历史版本。

⚠ **不要传 win-unpacked\ 和 builder-*.yml**，那是中间产物，白让人多下几百 MB。

⚠ **如果夸克的分享链接变了**（删了重建、或者换了文件夹，链接就会变）：
   第 4 步那条 `bun run manifest` 要用**新链接**重跑一遍，
   否则玩家的「去下载」还开着旧地址。改完 push + 催缓存，就这两下。

=== 7b GitHub Releases（备用）===

浏览器打开：

    https://github.com/ggboom514/fruit-fly-world/releases/new

1. Choose a tag 里输入 v1.29.0 → 点「Create new tag: v1.29.0 on publish」
2. Release title 填：果蝇世界 1.29.0
3. 描述框里写这一版改了什么（可以直接抄清单里那句 note）
4. 把下面三个文件拖进最下面「Attach binaries」那个框：
     dist\FruitFlyWorld-Setup-1.29.0.exe
     dist\FruitFlyWorld-Setup-1.29.0.exe.blockmap
     dist\FruitFlyWorld-1.29.0.exe
5. 点 Publish release

⚠ 要传 220MB 左右，可能等几分钟。
⚠ 说明.txt **不用**传这里 —— Release 页面自己就是说明。

⚠ 旧版本的安装包可以从 dist\ 里删掉，也可以留在网盘上（老链接别急着删，
   万一有人还在下）。


------------------------------------------------------------
第 8 步 · 自己验一次
------------------------------------------------------------

1. 浏览器打开这个，看到白底黑字的 JSON 才算数：

     https://cdn.jsdelivr.net/gh/ggboom514/fruit-fly-world@main/version.json

2. 装一个刚打好的包，打开 → 点工具箱上的齿轮「设置」：

     应该显示「版本 1.29.0」，点「检查更新」→「已经是最新的（1.29.0）」

3. 想验「有新版本」那条路，可以耍个花招：跑

     bun run manifest -- "https://pan.quark.cn/s/你的分享页" "测试"

   然后**手动把 version.json 里的版本号改成 99.0.0**，推上去、催缓存，
   打开游戏 → 设置卡上应该出现**金色的「有新版本 99.0.0」**和一颗「去下载」。
   点它应该用浏览器打开你的夸克分享页。

   验完把真那份改回 1.29.0 再推一次，别忘了催缓存。


============================================================
换下载链接，但不想重新打包
============================================================

场景：安装包放在夸克网盘 A 链接上，发出去了。三个月后 A 失效，你传到了 B。

下载地址写在**两个地方**：

    游戏程序内部（打包进去的）    ❌ 已经发给别人的 exe，改不了
    version.json 里的 url 栏      ✅ 改一下、push，立刻生效

好消息：**游戏优先用纸条里的地址**，程序内部那个只是纸条上没写时的备胎。

所以换链接**不用重新打包、不用重发安装包**，只要：

    bun run manifest -- "新的夸克链接" "1.29.0"
    git add version.json && git commit -m "换下载地址" && git push

再去催一次缓存。老玩家的游戏下次检查时读到的就是新链接，
点「去下载」会开到新网盘。

（这条行为有自检断言守着：纸条里给了 url 就必须用它，不能用程序里那个备胎。）


============================================================
常见翻车
============================================================

· 忘了第 1 步改 package.json
    → 打出来的包版本号还是旧的，纸条上写新的，游戏提示「有新版本」之后
      装了发现还是老版本

· 忘了第 4 步换纸条
    → 所有玩家一直显示「已经是最新的」。**不报错**，最容易被忽略

· 忘了第 6 步催缓存
    → 玩家最坏要等半天才收到提示

· 把 version.json 传到网盘去了
    → 没用。它得待在仓库里

· 忘了传 .blockmap
    → 当下没事。以后想加增量更新时，只能把所有历史版本重传一遍

· 改了 manifestUrl 却没重新打包
    → 清单地址是打进 asar 的，不重新打包不生效（这点和 url 那一栏**不一样**）
